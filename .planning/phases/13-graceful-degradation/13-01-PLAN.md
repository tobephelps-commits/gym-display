**3. Modify advanceZone() to skip unhealthy zones:**

Replace the current `advanceZone()` function with health-aware logic. The key design:
- After computing `toZone`, check if it's `'unhealthy'` in `zoneHealth`
- If unhealthy, keep incrementing `currentIndex` to find the next non-unhealthy zone
- **Cycle guard**: Track skip count. If we've skipped `rotationOrder.length` times (all zones unhealthy), stop and show the current zone anyway — never infinite loop
- `'degraded'` zones are NOT skipped — only `'unhealthy'` zones are skipped. Degraded means partial functionality, still worth showing.
- Log each skip: `console.log('Skipping unhealthy zone: ' + zoneName)`

Implementation:

```js
function advanceZone() {
  const fromZone = rotationOrder[currentIndex];
  let skipped = 0;
  let nextIndex = (currentIndex + 1) % rotationOrder.length;

  // Skip unhealthy zones (cycle guard: never skip more than full rotation)
  while (skipped < rotationOrder.length) {
    const candidate = rotationOrder[nextIndex];
    if (zoneHealth[candidate] === 'unhealthy') {
      console.log('Skipping unhealthy zone: ' + candidate);
      skipped++;
      nextIndex = (nextIndex + 1) % rotationOrder.length;
    } else {
      break;
    }
  }

  if (skipped > 0 && skipped < rotationOrder.length) {
    console.log('Skipped ' + skipped + ' unhealthy zone(s)');
  } else if (skipped >= rotationOrder.length) {
    console.log('All zones unhealthy — showing next zone anyway');
  }

  currentIndex = nextIndex;
  const toZone = rotationOrder[currentIndex];

  console.log('Zone transition: ' + fromZone + ' → ' + toZone);
  showZone(toZone);
  scheduleNext();

  // Sync server-side zone controller
  fetch('/api/zones/advance?source=kiosk', { method: 'POST' }).catch(function () {});
}
```

**Important: Do NOT change the existing per-zone skip logic in onRosterZoneActive, onLeaderboardZoneActive, or onAnnouncementsZoneActive.** Those handle "not configured" and "no data" cases which are different from health status. The health-based skip in advanceZone() is an additional layer — a zone can be "configured" but still "unhealthy" (e.g., Sheets configured but API erroring). Both layers work together: health skip prevents entering the zone at all, per-zone skip handles data-level emptiness.

**Recovery is automatic:** When the health monitor detects a zone has recovered (status changes from 'unhealthy' to 'healthy' or 'degraded'), the next /api/config poll (within 30 seconds) updates `zoneHealth`, and `advanceZone()` will stop skipping that zone. No special re-add logic needed — the zone was never removed from `rotationOrder`, just skipped.
