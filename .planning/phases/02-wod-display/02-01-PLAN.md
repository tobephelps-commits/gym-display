<task type="auto">
  <name>Task 1: Install dependencies and create WodScraper service</name>
  <files>package.json, services/wod-scraper.js</files>
  <action>
Install puppeteer-core, http-proxy-middleware, and tough-cookie:
```
npm install puppeteer-core http-proxy-middleware tough-cookie
```

Create services/wod-scraper.js — a singleton class that manages WodScreen browser automation:

**Constructor:**
- Accept config reference (from config-loader)
- Initialize state: browser=null, page=null, cookies=[], lastScreenshot=null, status='idle', wodPageUrl=null
- Listen for config changes to pick up credential updates

**launch() method:**
- Launch puppeteer-core with headless mode
- executablePath: On Windows dev, detect Chrome at common paths (Program Files\Google\Chrome\Application\chrome.exe, or use `where chrome` fallback). On Linux (Pi), use '/usr/bin/chromium-browser'.
- Args: --no-sandbox, --disable-setuid-sandbox, --disable-dev-shm-usage, --disable-gpu, --disable-software-rasterizer, --disable-extensions, --no-first-run, --no-zygote
- Set viewport to 1920x1080
- Set status to 'launched'

**login() method:**
- Navigate to config wodscreen.url (https://www.wodscreen.com)
- The login flow involves the /launch/index.html page which is a React SPA
- Wait for page load, look for login form elements
- Fill username/password from config.wodscreen.username/password
- Submit login form
- Wait for navigation/redirect after login
- After successful auth, look for the daily WOD launch button and click it
- Wait for the WOD page to render
- Store the resulting page URL in this.wodPageUrl
- Extract and store cookies via page.cookies()
- Set status to 'ready'
- Log success/failure with meaningful messages
- If login fails (timeout, wrong credentials, etc.), set status to 'error', log the error, keep lastScreenshot if available

**captureScreenshot() method:**
- Take a JPEG screenshot (quality: 85) of the current page
- Store in this.lastScreenshot as a Buffer
- Don't null out lastScreenshot on failure — keep last good one
- Log errors but don't throw

**startSessionLoop(intervalMs) method:**
- Every intervalMs (default: config wodscreen.refresh_interval_minutes * 60 * 1000, fallback 30 min):
  - Capture a fresh screenshot
  - Validate session is still alive (check if page still shows WOD content, not a login redirect)
  - If session expired, re-run login()
- Every day at a configurable hour (default 4 AM in config timezone), force full re-login to ensure fresh daily WOD

**getCookieString() method:**
- Return cookies formatted as Cookie header string for proxy injection
- Return null if no cookies available

**getStatus() method:**
- Return { status, wodPageUrl, lastScreenshotTime, cookieCount }

**shutdown() method:**
- Close browser gracefully

Export singleton instance. Don't auto-start — server.js will call launch() and login() on startup.

IMPORTANT: Use require() not import (project is CommonJS). Handle all Puppeteer operations with try/catch — never let an unhandled rejection crash the server. The WodScreen selectors are unknown and will need to be discovered during execution — use generous waitForSelector timeouts and fallback strategies (wait for any form-like element, try common patterns like input[type="email"], input[type="password"], button[type="submit"]).

<task type="auto">
  <name>Task 2: Create reverse proxy middleware and wire API endpoints</name>
  <files>services/wod-proxy.js, server.js</files>
  <action>
Create services/wod-proxy.js:
- Export a function createWodProxy(getCookiesFn) that returns Express middleware
- Use http-proxy-middleware's createProxyMiddleware:
  - target: 'https://wodscreen.com'
  - changeOrigin: true
  - selfHandleResponse: true (needed for responseInterceptor)
  - pathRewrite: { '^/wod-proxy': '' } — strip the /wod-proxy prefix
  - on.proxyRes: Use responseInterceptor to:
    - Delete x-frame-options header from response
    - Delete content-security-policy header
    - Delete content-security-policy-report-only header
    - For text/html responses, inject `<base href="https://wodscreen.com/">` in `<head>` so relative URLs resolve correctly
  - on.proxyReq: Inject Cookie header from getCookiesFn(), set Host header to 'wodscreen.com'
  - on.error: Log proxy errors, return 502 with JSON error

Update server.js to integrate WodScraper and proxy:

1. Require wod-scraper and wod-proxy at top
2. Mount proxy middleware: `app.use('/wod-proxy', createWodProxy(() => wodScraper.getCookieString()))`
3. Add API endpoints:
   - GET /api/wod/status — returns wodScraper.getStatus() (status, wodPageUrl, etc.)
   - GET /api/wod/screenshot — serves lastScreenshot as image/jpeg with Cache-Control: no-cache. Returns 503 JSON if no screenshot available.
   - POST /api/wod/refresh — triggers wodScraper.login() to force re-login/refresh (for manual recovery)
4. After server starts listening, call wodScraper.launch() then wodScraper.login() then wodScraper.startSessionLoop() — all in an async IIFE, with try/catch that logs errors but doesn't crash the server. The server must start and serve other zones even if WodScreen auth fails.

IMPORTANT: The proxy and scraper are best-effort — server.js must remain functional even if WodScreen is completely down. Wrap all WodScreen initialization in try/catch. The /api/wod/status endpoint should always work regardless of scraper state.
