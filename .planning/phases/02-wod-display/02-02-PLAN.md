<task type="auto">
  <name>Task 2: Add WOD status polling and display logic to frontend</name>
  <files>public/app.js</files>
  <action>
Add WOD display management to public/app.js:

**WOD state variables (at top of IIFE):**
- wodMode: 'loading' | 'iframe' | 'screenshot' | 'error'
- wodStatusPollTimer: null
- wodIframeLoaded: false

**initWod() function — called from init():**
1. Start polling GET /api/wod/status every 10 seconds
2. On each poll response:
   - If status === 'ready' and wodPageUrl exists:
     - Try iframe mode: set #wod-iframe src to '/wod-proxy/launch/index.html' (or whatever wodPageUrl path the scraper reports). The proxy will handle auth cookies.
     - Listen for iframe load event. On load, set wodMode to 'iframe', show iframe, hide others.
     - Set a 10-second timeout — if iframe doesn't fire load event, fall back to screenshot mode.
   - If status === 'ready' but iframe failed (timeout or error):
     - Switch to screenshot mode: set #wod-screenshot src to '/api/wod/screenshot?t=' + Date.now() (cache-bust)
     - On image load, show screenshot, hide iframe/loading/error
   - If status === 'error' or status === 'idle':
     - Try screenshot fallback first (may have a cached screenshot from before)
     - If no screenshot available (503), show error state
3. The status poll should be lightweight — don't reload iframe on every poll, only switch modes when status changes.

**showWodElement(elementId) helper:**
- Hide all .wod-display elements (add .hidden class)
- Show the specified element (remove .hidden class)
- Update wodMode state

**WOD zone visibility optimization:**
- When WOD zone is NOT the active zone (not visible due to rotation), pause iframe loading/screenshot refreshes to save resources
- When WOD zone becomes active, ensure the current best display is shown
- Use the existing zone transition logic — when showZone('wod') is called, trigger a WOD refresh check

**Screenshot refresh:**
- When in screenshot mode, refresh the screenshot image every 60 seconds (re-fetch /api/wod/screenshot with cache-bust) to pick up periodic captures from the scraper
- Only refresh while the WOD zone is active or about to become active

IMPORTANT:
- Do NOT break existing zone rotation logic. WOD display management is additive.
- All fetch calls must have .catch() handlers — network errors should degrade gracefully to the next fallback state, never throw unhandled.
- The iframe approach may not work if WodScreen's SPA detects it's in an iframe and breaks. If iframe errors, fall back to screenshot silently — no console spam.
