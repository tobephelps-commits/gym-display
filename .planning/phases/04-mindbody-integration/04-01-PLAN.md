<task type="auto">
  <name>Task 1: Install axios and create MindBody API client service</name>
  <files>package.json, services/mindbody.js</files>
  <action>
Install axios: `npm install axios`

Create services/mindbody.js as a singleton service (matching existing codebase pattern — see config-loader.js, video-manager.js).

MindBodyClient class with:

**Constructor:**
- Read config from config-loader: mindbody.api_key, mindbody.site_id, mindbody.username, mindbody.password
- Read system.timezone from config (for class time calculations)
- Initialize: token = null, tokenIssuedAt = null, cachedSchedule = [], cachedRoster = { classInfo: null, athletes: [], lastUpdated: null }
- Listen for config changes via configLoader.onConfigChange() to update credentials
- Base URL: 'https://api.mindbodyonline.com/public/v6'

**getToken():**
- If token exists and tokenIssuedAt is less than 6 days ago, return cached token
- Otherwise POST to /usertoken/issue with { Username, Password } and headers { 'Content-Type': 'application/json', 'Api-Key': apiKey, 'SiteId': siteId }
- Store response.data.AccessToken and tokenIssuedAt = Date.now()
- On error: log warning, return null (don't crash server)

**apiGet(path, params):**
- Get token via getToken(). If null, return null.
- GET BASE_URL + path with params and headers { 'Api-Key': apiKey, 'SiteId': siteId, 'Authorization': token }
- Return response.data
- On error: if 401, clear token (force refresh next call) and log. Otherwise log warning, return null.

**pollSchedule():**
- GET /class/classes with { StartDate: today, EndDate: today } (today as YYYY-MM-DD)
- Filter out cancelled classes (IsCancelled === true)
- Store in cachedSchedule
- Log class count

**getActiveClass():**
- From cachedSchedule, find class where now is between StartDateTime and EndDateTime
- Use system.timezone from config for time comparison. Since MindBody timestamps may be timezone-naive, parse them as local time strings.
- Return the active class object or null

**pollActiveRoster():**
- Call getActiveClass(). If no active class, set cachedRoster to empty and return.
- GET /class/classvisits with { ClassId: activeClass.Id }
- Extract visits from response: data.Class?.Visits || []
- Filter to signed-in athletes: visits.filter(v => v.SignedIn === true)
- Format display names: first name + last initial (e.g., "John S.") using Client?.FirstName and Client?.LastName with fallback to DisplayName. Handle nulls defensively.
- Deduplicate by ClientId (MindBody known issue with duplicate records)
- Store in cachedRoster: { classInfo: { name: activeClass.ClassDescription?.Name, startTime: activeClass.StartDateTime, endTime: activeClass.EndDateTime, coach: activeClass.Staff?.Name }, athletes: formattedNames, count: formattedNames.length, lastUpdated: Date.now() }

**startPolling():**
- Poll schedule immediately, then every poll_interval_minutes from config (default 5 min)
- Poll roster immediately, then every 60 seconds
- Store interval handles for cleanup
- If no credentials configured (api_key is placeholder), log warning and skip polling

**getSchedule():** Return cachedSchedule
**getRoster():** Return cachedRoster
**getStatus():** Return { configured: boolean, polling: boolean, lastSchedulePoll: timestamp, lastRosterPoll: timestamp, activeClass: boolean }

Export singleton instance.

<task type="auto">
  <name>Task 2: Add roster and schedule API endpoints to server</name>
  <files>server.js</files>
  <action>
Import mindbody service in server.js (same pattern as other services):
`const mindbodyClient = require('./services/mindbody');`

Add API endpoints:

**GET /api/roster** — Returns current roster data for frontend display:
```
{
  classInfo: { name, startTime, endTime, coach } | null,
  athletes: ["John S.", "Jane D.", ...],
  count: number,
  lastUpdated: timestamp | null
}
```
Implementation: `res.json(mindbodyClient.getRoster())`

**GET /api/schedule** — Returns today's class schedule:
```
{
  classes: [{ id, name, startTime, endTime, coach }],
  count: number
}
```
Implementation: Map cachedSchedule to simplified objects, return via `res.json()`

**GET /api/mindbody/status** — Returns service health:
Implementation: `res.json(mindbodyClient.getStatus())`

Add MindBody initialization in server startup (same best-effort pattern as WodScraper):
```javascript
// Initialize MindBody client — best-effort, server runs even if this fails
try {
  mindbodyClient.startPolling();
  console.log('[Server] MindBody polling started');
} catch (err) {
  console.error(`[Server] MindBody initialization failed (non-fatal): ${err.message}`);
}
```

Place this AFTER the server.listen callback, alongside the WodScraper initialization. MindBody init is synchronous (just starts timers), so no async needed.

Also add mindbody config to the sanitized /api/config response (no credentials):
Add to sanitized object: `mindbody: { configured: !!(current.mindbody && current.mindbody.api_key && current.mindbody.api_key !== 'your_api_key') }`
