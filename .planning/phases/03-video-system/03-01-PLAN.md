<task type="auto">
  <name>Task 1: Create video manager service and API endpoints</name>
  <files>services/video-manager.js, server.js, config.yaml</files>
  <action>
Create `services/video-manager.js` — a service that manages the YouTube video playlist:

1. **YouTube URL parsing** — `extractYouTubeId(url)` function using regex: `/(?:youtu\.be\/|youtube\.com\/(?:watch\?v=|embed\/|v\/))([a-zA-Z0-9_-]{11})/`. Returns video ID or null.

2. **Playlist state management:**
   - Constructor reads `videos` array from config via config-loader
   - Filter to only `enabled: true` entries
   - Parse each URL to extract YouTube video ID (skip entries where extraction fails — log warning)
   - Store as array of `{ videoId, title, url }` objects
   - Track `currentIndex` (reset to 0 on each zone activation)

3. **Config hot-reload:**
   - Listen to configLoader.onConfigChange
   - Re-parse videos array on change
   - Log additions/removals

4. **Public API:**
   - `getPlaylist()` — returns array of `{ videoId, title }` for enabled videos with valid YouTube IDs
   - `getVideoCount()` — returns count of enabled videos
   - `resetPlaylist()` — resets currentIndex to 0 (called when video zone activates)
   - `getCurrentVideo()` — returns current video or null if playlist exhausted
   - `advanceVideo()` — increments index, returns next video or null if playlist complete

5. Export as singleton instance (same pattern as zone-controller.js).

**Update config.yaml:** Keep existing `videos` array structure (already has url, title, enabled fields). Remove the Vimeo example entry since Vimeo is out of scope per CONTEXT.md. Add a comment noting YouTube URLs only.

**Update server.js:**
- Require video-manager
- Add `GET /api/videos` endpoint returning `{ videos: videoManager.getPlaylist(), count: videoManager.getVideoCount() }`
- Add `POST /api/videos/reset` endpoint that calls `videoManager.resetPlaylist()` and returns updated state
  </action>
  <verify>
Run `node -e "require('./services/video-manager.js')"` — no errors.
Run `npm start` and curl:
- `curl http://localhost:3000/api/videos` returns JSON with videos array and count
- `curl -X POST http://localhost:3000/api/videos/reset` returns success
  </verify>
  <done>Video manager service parses YouTube URLs from config, tracks playlist state, hot-reloads on config change. API endpoints return video list and support playlist reset.</done>
</task>

<task type="auto">

  <files>public/index.html, public/app.js, public/styles.css, services/zone-controller.js</files>
  <action>
**Update public/index.html:**
- Replace the video zone placeholder content with:
  - A `<div id="yt-player"></div>` for the YouTube IFrame API to target
  - A `<div id="video-no-content" class="video-display hidden">` showing "No videos configured" as fallback
  - Load YouTube IFrame API via CDN script tag: `<script src="https://www.youtube.com/iframe_api"></script>` BEFORE app.js

**Update public/app.js — add video zone management:**

1. **Video state variables:**
   - `videoPlaylist` (array from API), `videoIndex` (current position), `ytPlayer` (YT.Player instance), `youtubeReady` (boolean), `videoZoneActive` (boolean)

2. **YouTube IFrame API integration:**
   - Implement global `onYouTubeIframeAPIReady()` callback (must be on window — YouTube API requires this)
   - Create YT.Player on `yt-player` div with playerVars from RESEARCH.md: autoplay: 0 (we control play manually), controls: 0, modestbranding: 1, rel: 0, fs: 0, iv_load_policy: 3, disablekb: 1, playsinline: 1, enablejsapi: 1
   - `onReady`: set youtubeReady = true, set volume to 80
   - `onStateChange`: when YT.PlayerState.ENDED, call `playNextYouTube()`
   - `onError`: log error code, call `playNextYouTube()` to skip broken videos (error 101/150 = embedding disabled)

3. **Video zone activation/deactivation:**
   - `onVideoZoneActive()`: fetch fresh playlist from `/api/videos`, reset index to 0, call `POST /api/videos/reset`, start playing first video. If no videos, show "no content" fallback.
   - `onVideoZoneInactive()`: pause YouTube player if playing, set videoZoneActive = false.
   - Wire these into the existing `showZone()` function alongside the WOD zone callbacks.

4. **Playlist advancement:**
   - `playNextYouTube()`: increment videoIndex. If more videos, call `ytPlayer.loadVideoById(videoId)`. If playlist exhausted, signal video zone complete via `signalVideoZoneComplete()`.

5. **signalVideoZoneComplete():**
   - Call `POST /api/zones/advance` to tell the zone controller to move on.
   - This replaces the fixed `fallback_seconds` timer for the video zone.

6. **Zone controller play_full integration:**
   - In `scheduleNext()`, when currentZone is 'video' AND config has `play_full: true`, do NOT set a timeout (let video completion drive the transition).
   - Keep `fallback_seconds` as a safety net: set a maximum timeout that fires if videos haven't completed (prevents zone getting stuck if player errors out silently). When this safety timeout fires, also call `POST /api/zones/advance`.
   - Read `play_full` from config zones.video in fetchConfig.

**Update zone-controller.js:**
- In `_extractDurations`, for video zone: if `zones.video.play_full` is true, use `fallback_seconds` as a maximum timeout (safety net) rather than the primary duration. The actual advancement will come from the frontend calling `/api/zones/advance`.

**Update public/styles.css:**
- Add `#yt-player` styling: width 100%, height 100%, position absolute, top 0, left 0
- Style `#video-no-content` as centered text on dark background (consistent with other zone placeholders)
- Ensure the YouTube iframe fills the zone completely (the API creates an iframe inside the div)
