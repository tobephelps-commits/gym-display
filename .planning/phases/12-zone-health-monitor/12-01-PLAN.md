<task type="auto">
  <name>Task 1: Create ZoneHealthMonitor service</name>
  <files>services/zone-health-monitor.js</files>
  <action>
Create a new service `services/zone-health-monitor.js` that tracks health of each zone independently.

**Health state per zone:**
Each zone maintains: `status` (healthy/degraded/unhealthy), `lastSuccess` (timestamp of last successful check), `lastError` (last error message), `consecutiveFailures` (count), `lastCheck` (timestamp).

**Zone health check logic — what each zone checks:**

- **wod**: Call `wodScraper.getStatus()`. Healthy if `status !== 'error'` OR `hasCookies === true`. Unhealthy if status is `'error'` AND no cookies AND last success was > `staleness_minutes` ago. Degraded if status is `'error'` but cookies exist (stale but recoverable).
- **video**: Call `videoManager.getVideoCount()`. Healthy if count > 0. Unhealthy if count === 0 AND reels not enabled. Degraded if count === 0 but reels are enabled (partial content). Also check `reelsFetcher.getStatus()` — if both video count is 0 and reels count is 0, unhealthy.
- **roster**: Call `mindbodyClient.getStatus()`. Healthy if configured and polling. Unhealthy if not configured (expected — MindBody API key not activated). Degraded if configured but lastSchedulePoll is > `staleness_minutes` ago.
- **leaderboard**: Call `leaderboardService.isActive()` and `sheetsClient.getStatus()`. Healthy if sheets configured and leaderboard active. Unhealthy if sheets not configured. Degraded if sheets configured but leaderboard not active (no data in sheet).
- **announcements**: Same pattern as leaderboard — call `announcementsService.isActive()` and `sheetsClient.getStatus()`.

**Retry logic:**
- On each health check interval, if a zone is degraded/unhealthy, increment `consecutiveFailures`.
- After `max_retries` consecutive failures, mark unhealthy (stop retrying until manual refresh or next check cycle).
- Reset `consecutiveFailures` to 0 on any successful check.

**Configuration** (read from config via config-loader):
```yaml
health:
  check_interval_seconds: 60      # How often to run health checks
  staleness_minutes: 10           # Data older than this = degraded
  max_consecutive_failures: 5     # Failures before marking unhealthy
```

**API shape** — `getHealthStatus()` returns:
```js
{
  overall: 'healthy' | 'degraded' | 'unhealthy',  // worst status of all zones
  zones: {
    wod: { status, lastSuccess, lastError, consecutiveFailures, lastCheck },
    video: { status, lastSuccess, lastError, consecutiveFailures, lastCheck },
    roster: { status, lastSuccess, lastError, consecutiveFailures, lastCheck },
    leaderboard: { status, lastSuccess, lastError, consecutiveFailures, lastCheck },
    announcements: { status, lastSuccess, lastError, consecutiveFailures, lastCheck }
  },
  timestamp: ISO string
}
```

**Implementation approach:**
- Constructor takes service references (dependency injection, NOT require — keeps testable).
- `startMonitoring()` starts the check interval timer.
- `checkAll()` runs all zone checks, updates internal state.
- `getHealthStatus()` returns current snapshot.
- `getZoneHealth(zoneName)` returns single zone health.
- Export singleton that gets initialized with services in server.js.
- Listen for config changes via `configLoader.onConfigChange()` to update check interval.
- Console log format: `[HealthMonitor] zone=${name} status=${status} failures=${count}` on state transitions only (not every check — avoid log spam).

<task type="auto">
  <name>Task 2: Integrate health monitor into server and add API endpoint</name>
  <files>server.js, config.example.yaml</files>
  <action>
**In server.js:**

1. Import the health monitor: `const healthMonitor = require('./services/zone-health-monitor');`

2. After all services are initialized (after the `server.listen` callback), create and start the health monitor:
```js
const monitor = healthMonitor.create({
  wodScraper,
  videoManager,
  reelsFetcher,
  mindbodyClient,
  sheetsClient,
  leaderboardService,
  announcementsService,
  configLoader
});
monitor.startMonitoring();
```

3. Add a new API endpoint `GET /api/health/zones` (no auth required — health data is non-sensitive):
```js
app.get('/api/health/zones', (req, res) => {
  res.json(monitor.getHealthStatus());
});
```

4. Extend the existing `GET /api/admin/status` response to include health data. Add a `health` key to the response object:
```js
health: monitor.getHealthStatus()
```

5. Add a `POST /api/admin/refresh/:service` case for `'health'` that forces an immediate health check cycle:
```js
case 'health':
  monitor.checkAll();
  return res.json({ success: true, service, message: 'Health check triggered' });
```

**In config.example.yaml:**

Add a `health` section with documented defaults:

Place this section after the `system` section in the config file.
