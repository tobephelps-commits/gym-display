  <name>Task 1: Create NotificationService for Pushover and email delivery</name>
  <files>services/notification-service.js</files>
  <action>
Create a NotificationService class that handles notification delivery through two channels:

**Pushover (critical alerts):**
- Use `pushover-notifications` npm package
- Support priority levels: 0 (normal), 1 (high), 2 (emergency with retry/expire)
- Emergency priority: retry every 60s, expire after 3600s, sound 'siren'
- Constructor takes config object with `pushover.userKey` and `pushover.appToken`
- `sendPushover(title, message, priority)` method — returns Promise
- If Pushover not configured (no userKey/appToken), log warning once and skip silently

**Email (warning alerts):**
- Use `nodemailer` npm package with Gmail SMTP transport (simpler setup than Resend — no domain needed for a personal gym project)
- Constructor takes config object with `email.gmail_user`, `email.gmail_app_password`, `email.recipients` (array)
- `sendEmail(subject, body)` method — returns Promise
- If email not configured (missing gmail_user or recipients), log warning once and skip silently

**General patterns:**
- Export `create(config)` factory function matching project convention (see zone-health-monitor.js)
- Log send attempts and failures with `[Notifications]` prefix
- Never throw on send failure — log error and continue (notifications are best-effort, must not crash the display)
- Track `configured` state for each channel: `{ pushover: bool, email: bool }`
- Expose `getStatus()` returning `{ pushover: { configured, lastSend, lastError }, email: { configured, lastSend, lastError } }`

**Install dependencies:**
Run `npm install pushover-notifications nodemailer`

<task type="auto">
  <name>Task 2: Create AlertManager with tiering, deduplication, cooldowns, and batching</name>
  <files>services/alert-manager.js</files>
  <action>
Create an AlertManager class that receives zone status changes and routes them through intelligent alert logic before dispatching via NotificationService.

**Constructor:** Takes `notificationService` instance and `config` object with alert thresholds.

**Core method: `handleStatusChange(zoneName, oldStatus, newStatus, errorMsg)`**
Called by ZoneHealthMonitor on every status transition. Flow:

1. **Recovery check:** If newStatus is 'healthy' AND this zone was previously notified, call `handleRecovery(zoneName)` — send email "all clear" (require 2+ consecutive healthy checks stored in recentChecks before sending, to prevent premature recovery for flapping zones)

2. **Flapping detection:** Track last 10 check results per zone in `recentChecks` array. If transition rate >= 40% (4+ transitions in 10 checks), suppress alert and log `[AlertManager] zone=${zoneName} flapping detected, suppressing`

3. **Fingerprinting:** Generate alert fingerprint from `crypto.createHash('sha256').update(JSON.stringify({zone: zoneName, status: newStatus, category: categorizeError(errorMsg)})).digest('hex').slice(0, 16)`. Store active alerts in `Map<fingerprint, {firstSeen, lastSeen, count, notified}>`

4. **Cooldown check:** After sending, record timestamp. CRITICAL cooldown: 30 minutes. WARNING cooldown: 2 hours. Skip if on cooldown via `isOnCooldown(fingerprint, cooldownMs)`

5. **Severity classification:**
   - ALL zones unhealthy → CRITICAL (check all zone states)
   - Single zone UNHEALTHY for 3+ consecutive checks → CRITICAL
   - Single zone UNHEALTHY for 1-2 checks → WARNING
   - Zone DEGRADED for 3+ checks → WARNING
   - Recovery → INFO (email only)

6. **Routing:**
   - CRITICAL → `notificationService.sendPushover()` with priority 2 (emergency) + `notificationService.sendEmail()` immediately
   - WARNING → queue into `pendingWarnings` array, flush as batch digest after 30-second window via `setTimeout`
   - INFO (recovery) → `notificationService.sendEmail()` immediately

**Helper methods:**
- `categorizeError(errorMsg)` — normalize error messages to categories: 'api_error', 'stale_data', 'not_configured', 'no_content', 'check_error'
- `isFlapping(recentChecks)` — returns bool
- `getFingerprint(zone, status, category)` — returns hex string
- `isOnCooldown(fingerprint)` — returns bool
- `classifySeverity(zoneName, newStatus, consecutiveFailures)` — returns 'CRITICAL'|'WARNING'|'INFO'
- `queueWarning(alert)` — add to batch, start 30s timer if not running
- `flushWarningBatch()` — send all pending warnings as single email digest
- `handleRecovery(zoneName)` — send recovery email if zone was previously notified

**State:**
- `activeAlerts` — Map<fingerprint, alertState>
- `cooldowns` — Map<fingerprint, lastNotifiedTimestamp>
- `recentChecks` — Map<zoneName, Array<status>> (last 10 per zone)
- `pendingWarnings` — Array of warning alerts for batching
- `batchTimer` — setTimeout reference
- `notifiedZones` — Set<zoneName> for tracking which zones need recovery notifications
- `consecutiveHealthy` — Map<zoneName, count> for recovery threshold

**Expose:**
- `getAlertHistory()` — returns array of last 50 alerts (zone, severity, message, timestamp, notified) for Phase 15 dashboard
- `getStatus()` — returns `{ activeAlerts: count, cooldowns: count, flapping: [zoneNames] }`

**Export:** `create(notificationService, config)` factory function

**Configuration defaults (overridable via config):**
- `min_failures_warning: 1` — consecutive failures before WARNING
- `min_failures_critical: 3` — consecutive failures before CRITICAL
- `cooldown_critical_minutes: 30`
- `cooldown_warning_minutes: 120`
- `batch_window_seconds: 30`
- `flapping_threshold: 0.4`
- `flapping_window: 10`
- `recovery_threshold: 2` — consecutive healthy checks before recovery notification
