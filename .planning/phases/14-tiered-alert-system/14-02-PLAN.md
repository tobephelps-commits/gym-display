```yaml
# Alerts (v1.3 — Tiered Alert System)
# Critical alerts: Pushover push notifications (wake-up capable)
# Warning alerts: Email via Gmail
# Leave sections unconfigured to disable that channel
alerts:
  # Pushover for critical alerts (all zones down, persistent failures)
  # Sign up at pushover.net, buy app ($4.99 one-time)
  pushover:
    user_key: ""          # Your Pushover user key
    app_token: ""         # Your Pushover application token

  # Email for warning alerts (single zone down, degraded zones)
  # Uses Gmail with App Password — generate at Google Account > Security > App Passwords
  email:
    gmail_user: ""        # e.g. yourname@gmail.com
    gmail_app_password: "" # 16-character App Password (NOT your regular password)
    recipients:           # Who receives warning emails
      - ""                # e.g. owner@gmail.com

  # Alert thresholds (defaults are sensible, adjust if needed)
  thresholds:
    min_failures_warning: 1       # Consecutive failures before WARNING
    min_failures_critical: 3      # Consecutive failures before CRITICAL
    cooldown_critical_minutes: 30  # Don't re-alert CRITICAL for same issue within this window
    cooldown_warning_minutes: 120  # Don't re-alert WARNING for same issue within this window
    batch_window_seconds: 30       # Collect warnings for this long, send as digest
    recovery_threshold: 2          # Consecutive healthy checks before "all clear" notification
```

**server.js — Initialize alert services after health monitor:**

1. Add requires at top:
   ```javascript
   const notificationService = require('./services/notification-service');
   const alertManager = require('./services/alert-manager');
   ```

2. Add module-level variables near existing `let monitor = null`:
   ```javascript
   let notifications = null;
   let alerts = null;
   ```

3. After `monitor.startMonitoring()` in the server listen callback, add initialization:
   ```javascript
   // Initialize alert system (after health monitor)
   try {
     const alertsConfig = configLoader.getConfig().alerts || {};
     notifications = notificationService.create({
       pushover: {
         userKey: alertsConfig.pushover?.user_key || '',
         appToken: alertsConfig.pushover?.app_token || ''
       },
       email: {
         gmail_user: alertsConfig.email?.gmail_user || '',
         gmail_app_password: alertsConfig.email?.gmail_app_password || '',
         recipients: (alertsConfig.email?.recipients || []).filter(r => r)
       }
     });

     alerts = alertManager.create(notifications, alertsConfig.thresholds || {});
     console.log('[Server] Alert system initialized');
   } catch (err) {
     console.error(`[Server] Alert system initialization failed (non-fatal): ${err.message}`);
   }
   ```

   ```javascript
       history: alerts ? alerts.getAlertHistory() : []
     });
   });
   ```

<task type="auto">
  <name>Task 2: Hook AlertManager into ZoneHealthMonitor status transitions</name>
  <files>services/zone-health-monitor.js</files>
  <action>
Modify ZoneHealthMonitor to emit status changes to AlertManager.

1. **Add alert manager reference to constructor:**
   Add optional `alertManager` parameter to the services object. Store as `this._alertManager = services.alertManager || null`.

2. **Modify `_updateZone()` to call AlertManager on status transitions:**
   After the existing state transition logging block (`if (oldStatus !== zone.status)`), add:
   ```javascript
   // Notify alert manager of status transitions
   if (this._alertManager && oldStatus !== zone.status) {
     try {
       this._alertManager.handleStatusChange(zoneName, oldStatus, zone.status, zone.lastError);
     } catch (err) {
       console.error(`[HealthMonitor] Alert dispatch error: ${err.message}`);
     }
   }
   ```
   The try/catch ensures alert failures never disrupt health monitoring.

3. **Also call AlertManager for consecutive failure threshold crossings without status change:**
   Inside `_updateZone()`, after updating consecutiveFailures but before the status transition check, add a secondary alert trigger for when a zone is already unhealthy but accumulates more failures (the status doesn't change but the severity might escalate). Only trigger when `zone.consecutiveFailures` crosses the `min_failures_critical` threshold while already unhealthy:
   ```javascript
   // Alert on escalation within same status (e.g., unhealthy zone crossing critical threshold)
   if (this._alertManager && oldStatus === zone.status && zone.status !== STATUS.HEALTHY) {
     try {
       this._alertManager.handleStatusChange(zoneName, oldStatus, zone.status, zone.lastError);
     } catch (err) {
       console.error(`[HealthMonitor] Alert dispatch error: ${err.message}`);
     }
   }
   ```
   AlertManager's cooldown logic will prevent duplicate notifications — this just ensures the alert manager sees the updated consecutiveFailures count.

4. **Update server.js to pass alertManager into health monitor:**
   In server.js, after alert system initialization, inject alertManager into the health monitor. Add a `setAlertManager(alertManager)` method to ZoneHealthMonitor and call it:
   ```javascript
   // In ZoneHealthMonitor class:
   setAlertManager(alertManager) {
     this._alertManager = alertManager;
   }
   ```
   In server.js after alerts initialization:
   ```javascript
   if (monitor && alerts) {
     monitor.setAlertManager(alerts);
     console.log('[Server] Alert manager connected to health monitor');
   }
   ```
   This avoids circular dependency — health monitor creates first, alert manager creates second, then they're connected.
