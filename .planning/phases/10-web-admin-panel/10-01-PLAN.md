<task type="auto">
  <name>Task 1: Add admin API endpoints and auth middleware to server</name>
  <files>server.js, services/config-loader.js</files>
  <action>
  1. Add a simple bearer token auth middleware for admin routes. Read token from config.yaml `system.admin_token` (default: no auth if not set — allows easy first-use). The middleware checks `Authorization: Bearer <token>` header OR a `?token=<token>` query param (for browser navigation convenience). If `admin_token` is not configured, allow all requests (open access for local-only Pi).

  2. Add `saveConfig(updates)` method to ConfigLoader that:
     - Reads current config.yaml
     - Deep-merges `updates` into current config (only top-level keys in updates overwrite)
     - Writes back to config.yaml using js-yaml dump
     - The chokidar watcher will auto-detect the change and trigger reload
     - Returns the new config

  3. Add admin API endpoints in server.js (protected by admin auth middleware):
     - `GET /api/admin/status` — Aggregates ALL service statuses into one response:
       ```json
       {
         "uptime": number,
         "zones": { currentZone, nextZone, boostActive, rotationOrder },
         "wod": { status, lastLogin, lastScreenshot },
         "mindbody": { configured, polling, lastSchedulePoll, activeClass },
         "sheets": { configured, polling, lastPoll, tabs },
         "videos": { count, source },
         "reels": { enabled, count },
         "leaderboard": { active },
         "announcements": { active, count }
       }
       ```
     - `GET /api/admin/config/full` — Returns full config (WITH credentials masked as "***") for the config editor. Mask: wodscreen.password, mindbody.api_key, mindbody.password, sheets.credentials_file contents (show path only).
     - `POST /api/admin/config` — Accepts JSON body with config section updates. Validates that body is an object, calls `configLoader.saveConfig(body)`. Returns `{ success: true, message: 'Config updated' }`. On error returns 500 with error message.
     - `POST /api/admin/refresh/:service` — Trigger manual refresh for a service. Supported services: `wod` (calls wodScraper.login()), `sheets` (calls sheetsClient.poll()), `videos` (calls videoManager resetPlaylist). Returns `{ success: true, service, message }` or 500 on error.

  4. Serve admin static files: Add `app.use('/admin', adminAuthMiddleware, express.static(path.join(__dirname, 'public', 'admin')))` BEFORE the general static middleware. Use same no-cache headers.

  5. Add `admin_token` field to config.example.yaml under `system` section with comment explaining it's optional.
  </action>
  <verify>
  - Server starts without errors: `node -e "require('./server')" && echo OK` (or start and check no crash)
  - `curl http://localhost:3000/api/admin/status` returns aggregated status JSON
  - `curl http://localhost:3000/api/admin/config/full` returns config with masked credentials
  </verify>
  <done>Admin API endpoints respond correctly, auth middleware works, config save method exists on ConfigLoader</done>

<task type="auto">

  <files>public/admin/index.html, public/admin/admin.css, public/admin/admin.js</files>
  <action>
  Create `public/admin/` directory with:

  1. `index.html` — Single-page admin shell:
     - Clean, minimal HTML structure with dark theme (gym-appropriate)
     - Header: "BigBarn Admin" title + system uptime badge
     - Navigation tabs: "Dashboard" and "Settings" (two main sections)
     - Content area: `<div id="page-dashboard">` and `<div id="page-settings">` (shown/hidden by tab clicks)
     - Both pages are empty placeholders for now (Plans 02 and 03 will populate)
     - Load admin.css and admin.js
     - Include a `<div id="toast">` for success/error notifications
     - No frameworks — vanilla HTML/CSS/JS matching project conventions

  2. `admin.css` — Admin-specific styles:
     - Dark theme: background #1a1a2e, text #eee, accent #0f3460
     - Responsive layout (works on phone and desktop — admin may use phone to control)
     - Card component: `.card` with subtle border, padding, background #16213e
     - Status indicators: `.status-ok` (green), `.status-warning` (yellow), `.status-error` (red)
     - Navigation tabs: horizontal tab bar with active state
     - Form elements: styled inputs, selects, buttons matching dark theme
     - Toast notification: fixed position, slide-in animation
     - Grid layout for dashboard cards: CSS grid, responsive columns

  3. `admin.js` — Admin-specific JavaScript:
     - Tab navigation: show/hide page sections on tab click, update URL hash
     - `api(url, options)` helper: wraps fetch with `/api/admin/` prefix, handles errors, returns JSON
     - `showToast(message, type)` helper: show success/error toast for 3 seconds
     - `formatUptime(seconds)` helper: converts seconds to "Xd Xh Xm" format
     - `formatTimestamp(iso)` helper: converts ISO timestamp to relative "X min ago" format
     - On page load: read URL hash to show correct tab, default to dashboard
     - Export/expose: `window.AdminApp = { api, showToast, formatUptime, formatTimestamp }` for use by page-specific code embedded in HTML sections

  Keep the admin UI simple and functional — this is a utility panel, not a showpiece. Prioritize usability on mobile (coach controlling display from phone during class).
