<task type="auto">
  <name>Task 1: Build zone and system settings forms</name>
  <files>public/admin/index.html, public/admin/admin.css</files>
  <action>
  Populate the `#page-settings` section in admin/index.html with organized settings forms:

  1. **Zone Settings Card**:
     - Rotation order: Sortable list of zone names (wod, video, roster, leaderboard, announcements). Use simple up/down arrow buttons to reorder (no drag-and-drop library needed). Show which zones are currently in rotation with checkboxes to include/exclude.
     - Per-zone duration inputs: Number inputs for each zone's `duration_seconds` (labeled clearly: "WOD Duration", "Roster Duration", etc.)
     - Video zone: Checkbox for `play_full` (play full video vs fixed duration)
     - Roster boost: `boost_before_class_minutes` (number input), `boost_frequency` (number input)
     - "Save Zone Settings" button

  2. **Video Playlist Card** (only if source is 'config' — show info message if source is 'sheets'):
     - List current videos from config with title, URL, enabled toggle
     - "Add Video" button: shows inline form with URL + title inputs
     - Remove button per video (with confirm)
     - "Save Playlist" button
     - If playlist source is 'sheets': show read-only message "Playlist managed via Google Sheets" with link info

  3. **System Settings Card**:
     - Port number (read-only display — changing requires restart)
     - Log level dropdown (debug/info/warn/error)
     - Timezone input
     - Screen off/on times (time inputs)
     - Admin token input (password field, shows current masked value)
     - "Save System Settings" button

  4. **Form behavior (JavaScript)**:
     - On page load: fetch `GET /api/admin/config/full`, populate all form fields
     - Each "Save" button: collect form section data, POST to `/api/admin/config` with the relevant config section, show toast on success/error
     - Input validation: duration must be positive number, URLs must be valid, etc. Show inline error messages.
     - After successful save: re-fetch config to confirm changes took effect (config.yaml watcher will trigger reload)
     - Disable save button while request is in-flight (prevent double-submit)

  5. **Additional CSS** in admin.css if needed:
     - Form group styles: label + input with proper spacing
     - Inline error message styles (red text below input)
     - Sortable list styles (zone order items with up/down buttons)
     - Read-only info message style (muted card with info icon)

  Keep forms simple and functional. Each section saves independently — no "save all" button. This lets the coach change zone durations without worrying about video playlist changes.
  </action>
  <verify>
  - Settings page loads with current config values populated
  - Zone duration inputs show current values and accept changes
  - Rotation order can be reordered with up/down buttons
  - Save Zone Settings button persists changes to config.yaml
  - Video playlist shows current videos (or Sheets message)
  - System settings form populates and saves correctly
  - After saving, re-fetching config confirms changes persisted
  </verify>
  <done>Settings page provides complete config editing with validation, save, and confirmation</done>
</task>

<task type="auto">
  <name>Task 2: Add config backup and validation to save endpoint</name>
  <files>services/config-loader.js</files>
  <action>
  Enhance the `saveConfig()` method added in Plan 01:

  1. **Backup before save**: Before writing changes, copy current config.yaml to config.yaml.bak (overwrite previous backup). This gives a one-level undo if a bad config is saved.

  2. **Validation**: Before saving, validate critical fields:
     - `zones.rotation_order` must be an array of valid zone names (wod, video, roster, leaderboard, announcements)
     - Duration values must be positive numbers
     - `system.port` must be 1-65535
     - If validation fails, return error (don't write file)

  3. Add `getConfigPath()` method that returns the config file path (useful for the admin UI to show file location).

  4. Add `restoreBackup()` method that copies config.yaml.bak back to config.yaml (the watcher will trigger reload). Returns true on success, false if no backup exists.

  5. Add corresponding endpoints in server.js if not already present:
     - `POST /api/admin/config/restore` — calls configLoader.restoreBackup(), returns success/error
  </action>
  <verify>
  - Saving config creates config.yaml.bak
  - Invalid config values are rejected with error message
  - `POST /api/admin/config/restore` restores from backup
  - Config reload still triggers correctly after programmatic save
  </verify>
  <done>Config save has backup, validation, and restore capability</done>
