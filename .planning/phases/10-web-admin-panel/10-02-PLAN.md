<task type="auto">
  <name>Task 1: Build status dashboard with live polling</name>
  <files>public/admin/index.html</files>
  <action>
  Populate the `#page-dashboard` section in admin/index.html with:

  1. **Zone Status Card** (top, prominent):
     - Current zone name (large text, color-coded by zone type)
     - Next zone indicator
     - Rotation order display (visual pills showing order, highlight current)
     - Boost status indicator (active/inactive)
     - "Advance Zone" button (calls `POST /api/zones/advance`, shows toast on success)

  2. **Service Health Grid** (2-column grid on desktop, 1-column mobile):
     Each service gets a card with status indicator (green/yellow/red dot):

     - **WOD Service**: Status (running/error), last login time, last screenshot time. "Refresh WOD" button (calls `POST /api/admin/refresh/wod`). Small WOD screenshot preview (img src="/api/wod/screenshot", 200px wide).
     - **MindBody**: Configured yes/no, polling status, last poll time, active class yes/no. Show current class name + roster count if active.
     - **Google Sheets**: Configured yes/no, polling status, last poll time, tab list. "Sync Now" button (calls `POST /api/admin/refresh/sheets`).
     - **Videos**: Source (sheets/config), video count, current playlist. "Reset Playlist" button (calls `POST /api/videos/reset`).
     - **Reels**: Enabled yes/no, reel count.
     - **Leaderboard**: Active yes/no (green if active, grey if no data).
     - **Announcements**: Active yes/no, announcement count.

  3. **System Info** (footer card):
     - Server uptime (formatted)
     - Node.js environment
     - Last config reload timestamp

  4. **Auto-refresh**: Poll `GET /api/admin/status` every 10 seconds. Update all cards with fresh data. Use the `AdminApp.api()` helper from admin.js. On fetch error, show a subtle "Connection lost" banner (don't spam toasts).

  5. **JavaScript**: Add dashboard-specific JS in a `<script>` block within the dashboard page section (or at bottom of index.html). Functions:
     - `loadDashboard()` — fetches /api/admin/status + /api/zones/current + /api/roster, populates all cards
     - `startDashboardPolling()` / `stopDashboardPolling()` — 10-second interval, stop when switching to Settings tab
     - Button click handlers for Advance Zone, Refresh WOD, Sync Sheets, Reset Playlist
     - Each button shows loading state during request, toast on success/error

  Keep the dashboard read-heavy and action-light. The primary purpose is monitoring, with a few quick controls for common actions. Use semantic HTML and the card/grid CSS classes from admin.css.
  </action>
  <verify>
  - Dashboard loads and shows current zone state
  - Service health cards show correct status indicators
  - WOD screenshot preview loads (if WOD service running)
  - Advance Zone button works (zone changes, toast shows)
  - Auto-refresh updates data every 10 seconds without flicker
  </verify>
  <done>Dashboard page shows complete system status with live updates and working control buttons</done>
</task>
