**public/styles.css — Leaderboard zone styling:**

Design for **1080p TV viewed from 20+ feet** (same constraint as roster zone). Competition energy is key.

Zone background: dark (#0d1117 or similar dark charcoal — distinct from other zone backgrounds).

**Layout:** Three team cards side by side in a row (flexbox), each taking ~1/3 width with small gaps. First-place team card is slightly larger/elevated.

**Team card structure:**
- Team color as accent (left border or top bar, 6px solid using team color from API)
- Rank badge: large "1st", "2nd", "3rd" in top corner
- Team name: large bold text in team color (3rem+)
- Team total: very large score number (5rem+, bold, team color)
- "pts" label smaller next to total
- Divider line
- Member list below: each member as `Name — Points` rows
  - Member names: 1.8-2rem for readability from distance
  - Points right-aligned
  - Alternate row subtle background for readability

**Responsive density for member lists** (follow roster pattern):
- ≤8 members per team: normal size (2rem)
- 9-15 members: compact (1.6rem)
- 16+ members: dense (1.3rem) — unlikely but handle it

**First-place emphasis:**
- Slightly larger card (flex: 1.2 vs flex: 1 for others)
- Subtle glow or brighter accent

**Important:** Use vanilla CSS only (no frameworks). Follow existing codebase conventions:
- Use `.hidden` class for state toggling
- Use `position: absolute` for state stacking within zone
- Background color distinct from other zones

<task type="auto">
  <name>Task 2: Wire up leaderboard zone in app.js</name>

  <action>
Follow the roster zone pattern exactly for zone lifecycle. Add to existing app.js:

**State variables** (add near other zone state vars):
```javascript
var leaderboardPollTimer = null;
var leaderboardLastData = null;
var leaderboardConfigured = false;
```

**`onLeaderboardZoneActive()`:**
1. Check `leaderboardConfigured` — if false, `setTimeout(advanceZone, 0)` and return (skip zone)
2. Fetch `/api/leaderboard`
3. If response has `active: false` or empty teams array → `advanceZone()` (skip)
4. Call `updateLeaderboardDisplay(data)`
5. Store `leaderboardLastData = data`
6. Start polling: `leaderboardPollTimer = setInterval(pollLeaderboard, 30000)` (30s — less frequent than roster since Sheets updates are slower)

**`onLeaderboardZoneInactive()`:**
- Clear `leaderboardPollTimer`

**`pollLeaderboard()`:**
- Fetch `/api/leaderboard`, update display, keep stale data on error (roster pattern)

**`updateLeaderboardDisplay(data)`:**
- If `!data || !data.active || !data.teams.length`: show `leaderboard-empty` state, return
- Show `leaderboard-display` state
- Clear `leaderboard-teams` container
- For each team in `data.teams`:
  - Create team card div with class `leaderboard-team-card`
  - Set CSS custom property or inline style for team color border/accent (use `team.color` from API)
  - Add rank badge (1st/2nd/3rd), team name, total score
  - Add member list: iterate `team.members`, create row for each with name and points
  - Apply density class based on member count (normal/compact/dense)
  - First-place card gets additional `.first-place` class
- Append all cards to `leaderboard-teams`

**`showLeaderboardState(stateId)`:**
- Same pattern as `showRosterState()` — hide all `.leaderboard-state`, show target by ID

**Integration into `showZone()`:**
- Add to deactivation block: `if (previousZone === 'leaderboard') onLeaderboardZoneInactive();`
- Add to activation block: `if (zoneName === 'leaderboard') onLeaderboardZoneActive();`

**Integration into `init()` and `fetchConfig()`:**
- Read `leaderboardConfigured` from config response (the `leaderboard.active` field from `/api/config`)
- Same pattern as `mindbodyConfigured` for roster
