<task type="auto">
  <name>Task 2: Add Health page JavaScript module</name>
  <files>public/admin/index.html</files>
  <action>
Add an inline script block in index.html (after the existing Dashboard module script, following the same IIFE pattern) that implements the Health page module.

**Data sources** (both existing endpoints, no new API needed):
- `GET /api/admin/status` → `.health` field contains `{ overall, zones: { wod: { status, lastSuccess, lastError, consecutiveFailures, lastCheck }, ... }, timestamp }`
- `GET /api/admin/alerts` → `{ notifications: { pushover: {...}, email: {...} }, alerts: { activeAlerts, cooldowns, flapping }, history: [{ zone, severity, message, timestamp, notified }, ...] }`

**Implementation:**

1. `loadHealth()` function that fetches both endpoints in parallel (`Promise.all`), then calls:
   - `renderZoneHealthCards(healthData)` — updates the 5 zone cards with status dots, timestamps, error messages
   - `renderErrorHistory(alertHistory)` — populates the error history table (reverse chronological)
   - `renderAlertStatus(alertsData, notificationsData)` — updates alert summary card

2. `renderZoneHealthCards(healthData)`:
   - For each zone in healthData.zones, update the corresponding card's status dot, status text, last success (use `formatTimestamp` from AdminApp), last error, consecutive failures
   - Set card left-border color: healthy=#48bb78, degraded=#ecc94b, unhealthy=#fc8181
   - Show overall system health status at top

3. `renderErrorHistory(history)`:
   - Reverse the array (most recent first)
   - Build table rows with severity badges
   - Format timestamps with `formatTimestamp` from AdminApp
   - Truncate long messages to ~80 chars with title tooltip for full text
   - If history is empty, show "No alerts recorded" message

4. `renderAlertStatus(alertsData, notificationsData)`:
   - Show active alerts count, cooldowns count
   - List flapping zones or "None"
   - Show Pushover configured/enabled status
   - Show Email configured/enabled status

5. Polling: Start 15-second polling when Health tab is active, stop when switching away (same pattern as Dashboard module's `startDashboardPolling`/`stopDashboardPolling`).

6. Hook into the existing tab navigation click handlers to start/stop Health polling (same pattern as Dashboard).

**Use existing AdminApp utilities:** `api()`, `formatTimestamp()`, `formatUptime()`, `showToast()`.

**Do NOT use modern JS syntax** that isn't already in the codebase — the existing code uses `var`, `function(){}`, `.forEach`, `Promise.then()`. Follow this style consistently. The Dashboard module uses this pattern and the Health module should match exactly.
