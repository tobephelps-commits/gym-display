# Milestone v1.4: Video Scheduling

**Status:** SHIPPED 2026-02-25

## Overview

Day-of-week video scheduling via Google Sheets, allowing coaches to assign specific days for each video. Also included video focus mode, frontend watchdog for display recovery, and operational polish (alert suppression, clean restarts, Sheets setup instructions).

## Phases

### Phase 16: Day-of-Week Video Scheduling

**Goal**: Allow videos in the playlist to be assigned specific days of the week they should play, configured via a new column in the Google Sheets Playlist tab.
**Depends on**: Phase 15
**Plans**: 1

Plans:
- [x] 16-01: Day-of-week filtering, admin panel, config docs — completed 2026-02-24

**Details:**
- VideoManager filters playlist by current day-of-week using timezone-aware isScheduledForToday() helper
- Admin panel displays editable Days column for each video in playlist
- config.example.yaml documents the new days field with examples
- Fully backward compatible: videos without days field play every day
- Playlist naturally updates at midnight when day rolls over (existing 60s check handles it)
- Used en-US short weekday format (Mon, Tue, etc.) for consistent day matching

**Additional work (post-plan):**
- Per-zone alert suppression via suppressed_zones config
- Fix: suppress notifications for degraded zones below critical threshold
- Fix: treat unconfigured MindBody as degraded, not unhealthy
- Fix: add SIGTERM handler for clean systemctl restart
- Feat: video focus mode and Sheets instructions tab in admin panel
- Fix: treat day-of-week filtered empty playlist as healthy
- Feat: frontend watchdog for automatic display recovery

## Milestone Summary

**Key Decisions:**
- Day abbreviations use en-US short format (Mon,Tue,Wed,Thu,Fri,Sat,Sun) for consistency with toLocaleDateString
- Day filtering applied at playlist build time, not at video selection time — playlist naturally changes at midnight
- Frontend watchdog monitors for blank/stuck screens and triggers automatic recovery

**Issues Resolved:**
- Day-of-week filtered empty playlists incorrectly triggered unhealthy status (fixed: treated as healthy)
- MindBody unconfigured state triggered unhealthy alerts (fixed: treated as degraded)
- Degraded zones below critical threshold triggered unnecessary notifications (fixed: suppressed)
- systemctl restart left orphaned processes (fixed: SIGTERM handler)

**Issues Deferred:**
- MindBody API key activation for site 24936 (external dependency)
- Pushover and Gmail credential configuration

**Technical Debt Incurred:**
- None significant
