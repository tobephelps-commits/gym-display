# Milestone v1.3: Resilience

**Status:** SHIPPED 2026-02-24
**Phases:** 12-15
**Total Plans:** 5

## Overview

Comprehensive error handling, auto-recovery, and admin notification across all zones for unattended operation. Added zone health monitoring, graceful degradation (unhealthy zones auto-skipped), tiered alert system (Pushover + email), and a Health tab in the admin panel for visual monitoring.

## Phases

**Goal**: Track health of each zone (WOD, video, leaderboard, announcements, roster), detect failures (stalls, API errors, load failures, playback errors), implement retry logic before marking a zone unhealthy
**Depends on**: Previous milestone complete
**Plans**: 1

Plans:
- [x] 12-01: Zone Health Monitor service + server integration — completed 2026-02-24

- Created ZoneHealthMonitor service with dependency-injected service references

### Phase 13: Graceful Degradation

**Goal**: Unhealthy zones get automatically skipped in rotation, re-added when they recover — rotation never stalls or shows broken content
**Depends on**: Phase 12
**Plans**: 1

Plans:

**Details:**

- /api/zones endpoint added (fixes frontend poll 404)

### Phase 14: Tiered Alert System

**Goal**: SMS for critical failures (display completely down, all zones failed), email for warnings (single zone down, API errors, download failures). Configurable thresholds.
**Depends on**: Phase 13
**Plans**: 2

Plans:
- [x] 14-01: Core alert services (NotificationService + AlertManager) — completed 2026-02-24

- Dependencies added: pushover-notifications, nodemailer

## Milestone Summary

**Key Decisions:**
- Dependency injection over require() for ZoneHealthMonitor (testability)
- Piggyback health data on existing /api/config poll (no new poll loop)
- Only skip 'unhealthy' zones, not 'degraded' (partial data is still useful)
- Cycle guard: show next zone if all unhealthy (prevent infinite loop)
- Gmail SMTP via nodemailer instead of Resend (no custom domain needed)
- In-memory alert state, no persistence (Pi reboots nightly, fresh alerts on reboot is useful)
- Late-binding via setAlertManager() to avoid circular dependency
- Alert failures wrapped in try/catch at every boundary (never crash the display)

**Issues Resolved:**
- Zone failures no longer show broken content to gym members
- Admin can now monitor zone health without SSH access
- Alert notifications provide proactive failure awareness

**Issues Deferred:**
- MindBody API key activation for site 24936 (external dependency, not a code issue)

**Technical Debt Incurred:**
- None significant — all services follow existing project patterns
