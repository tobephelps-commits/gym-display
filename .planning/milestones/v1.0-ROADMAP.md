# Milestone v1.0: MVP

**Status:** SHIPPED 2026-02-23
**Phases:** 1-5
**Total Plans:** 12 + 1 fix

## Overview

Build a Raspberry Pi 5-based gym display that rotates through three full-screen zones (WOD, video playlist, class roster) on a wall-mounted 1080p TV. Starting from project skeleton and config system, each phase adds one major capability, culminating in a deployment-ready system with auto-start, crash recovery, and off-hours TV control.

## Milestone Summary

**Key Decisions:**

- Puppeteer screenshot approach for WodScreen (no public API available)
- YAML config over database (single-file simplicity, SSH-editable)
- Vanilla JS frontend (minimal dependencies, fast on Pi hardware)
- Destroy/recreate YouTube player per zone visit (eliminates stale postMessage events)
- --disable-gpu-compositing for Chromium on Pi/Wayland (fixes white iframe rendering)
- Wayland/labwc required (RPi Connect needs Wayland, not X11)
- instaloader for Instagram Reels (no API key, scrapes public profiles)
- Tailscale for SSH access (Pi on different network than dev machine)

**Issues Resolved:**

- WodScreen authorization popup breaking iframe display (proxy domain mismatch + gym auth step)
- YouTube videos playing back-to-back instead of one-per-rotation (stale postMessage events from persistent iframe)
- White/grey YouTube iframe rendering on Raspberry Pi (Chromium GPU compositing bug)
- Instagram rate limiting from Pi IP (workaround: pre-cache reels from Windows, scp to Pi)
- Chromium kiosk GNOME Keyring prompt (--password-store=basic flag)
- Puppeteer headless on Wayland (--ozone-platform=headless flag)

**Issues Deferred:**

- Instagram instaloader blocked from Pi IP — must refresh reels manually from Windows via scp

**Technical Debt Incurred:**

- Reels cache requires manual refresh from Windows (no automated pipeline)
- MindBody using sandbox credentials (needs production API key for real roster data)
